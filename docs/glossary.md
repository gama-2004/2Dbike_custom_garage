# 用語集

## 仕様(BuildSpec)

1台のバイクをどう組んだかを表すデータ。次の4つで構成される。

| 項目 | 例 |
| --- | --- |
| どのベース車両か | アメリカン |
| 各部位にどのパーツを付けたか | タンク=ピーナッツ、ハンドル=エイプハンガー、マフラー=フィッシュテール … |
| 各塗装部位の色 | メインカラー=ワインレッド、サブカラー=オレンジ … |
| ローダウン量 | 12mm |

仕様があれば、車両図とビルドシート(重量、シート高など)は計算して作り直せる。

同じ形のデータが、場面ごとに次の名前で登場する。

| 呼び方 | 意味 |
| --- | --- |
| 標準仕様 | ベース車両の買ったままの状態。比較のビフォーにもなる |
| プリセット | ボバー、チョッパーなど、あらかじめ用意した仕様 |
| 現在の仕様 | 利用者がいま編集している仕様。作業状態(Workspace)が持つ |
| 保存仕様 | 名前と日時を付けて保存した仕様(SavedBuild) |
| 変更履歴 | 1回の変更の前と後、2つの仕様の組(EditCommand) |

> 注意: ソフトウェア工学では「仕様」は普通「要求仕様」「機能仕様」を指す。卒論では最初に「本研究では、車両・パーツ・色・車高の組み合わせを『仕様』と呼ぶ」と定義するか、「カスタム構成」「ビルド」などに言い換える。

## そのほか

| 用語 | 意味 |
| --- | --- |
| ベース車両 | カスタムの土台にする車両。今はスーパースポーツとアメリカンの2種 |
| 部位 | タンク、マフラーなど、パーツを付ける場所 |
| 塗装部位 | メインカラー、フレームなど、色を塗り分ける場所 |
| 組み合わせ制約 | 同時に付けられない／一緒に必要、などのパーツの組み合わせルール |
| ビルドシート | 部品・色の一覧と、シート高・最低地上高・車両重量の目安をまとめた表 |
| スタイル名 | 組み合わせから自動で判定する呼び名(チョッパー、ボバーなど) |
