# ユースケース記述

## 2-01 車両ベース選択

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 車両ベース選択 |
| アクター | 利用者 |
| 概要 | カスタムの土台にするベース車両を一覧から選び、その標準仕様を車両ビューに表示する。 |
| 事前条件 | カタログに1台以上のベース車両が登録されている。 |
| 事後条件 | 選んだ車両の標準仕様が作業状態に設定され、車両ビューとパーツ棚がその車両の内容になる。変更履歴は空になる。 |

**基本フロー**

1. 利用者はカスタム画面を開く。
2. システムはカタログから車両一覧を取得し、表示する。
3. 利用者は車両を選ぶ。
4. システムは車両の標準仕様の複製を、作業状態の現在の仕様に設定する。
5. システムは変更履歴を消去する。
6. システムは車両図を描画して車両ビューに表示し、パーツ棚をその車両の部位で組み立て直す。

**代替フロー**

- 3a. 未保存の変更がある場合、システムは「現在の仕様は破棄されます」と確認する。利用者が取り消すと3に戻る。

**例外フロー**

- 2a. 車両が1台も登録されていない場合、システムは「車両が登録されていません」と表示して終了する。

図: [ロバストネス図](svg/uc2_01_robustness.svg) ／ [シーケンス図](svg/uc2_01_sequence.svg)

## 2-02 ベース車両追加

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ベース車両追加 |
| アクター | 管理者 |
| 概要 | 管理者が車両定義ファイル(JSON)を読み込み、新しいベース車両をカタログに登録する。定義ファイルには部位、塗装部位、標準仕様、描画データを含む。 |
| 事前条件 | 管理者が管理画面を開いている。 |
| 事後条件 | 新しい車両がカタログに登録され、2-01の車両一覧に表示される。 |

**基本フロー**

1. 管理者は「車両を追加」を選び、車両定義ファイルを指定する。
2. システムはファイルを読み込み、内容を検証する(必須項目、部位IDの重複、標準仕様がすべての部位を満たしているか)。
3. システムは同じIDの車両がないか確認し、車両を生成する。
4. システムは標準仕様で車両図を描画し、プレビューとして表示する。
5. 管理者は登録を確定する。
6. システムは車両をカタログに登録する。
7. システムは「登録しました」と表示する。

**代替フロー**

- 5a. 管理者が取り消した場合、システムは何も登録せずに終了する。

**例外フロー**

- 2a. 検証エラーがある場合、システムはエラーの項目と理由を一覧で表示し、登録しない。
- 3a. 同じIDの車両がある場合、システムは上書きするかを確認する。

図: [ロバストネス図](svg/uc2_02_robustness.svg) ／ [シーケンス図](svg/uc2_02_sequence.svg)

## 2-03 パーツ追加

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | パーツ追加 |
| アクター | 管理者 |
| 概要 | 登録済みの車両に、新しいパーツ(名称、重量、価格、描画データ)と、そのパーツに関わる組み合わせ制約を追加する。 |
| 事前条件 | 対象のベース車両がカタログに登録されている。 |
| 事後条件 | パーツと制約がカタログに登録され、利用者のパーツ棚に選択肢として表示される。 |

**基本フロー**

1. 管理者は対象の車両と部位を選び、パーツ定義ファイルを指定する。
2. システムはファイルを読み込み、内容を検証する(必須項目、部位の存在、描画データの形式)。
3. システムはパーツを生成する。定義に制約が含まれていれば、参照先のパーツが存在するか確認して制約を生成する。
4. システムは標準仕様にこのパーツを付けた車両図を描画し、プレビューとして表示する。
5. 管理者は登録を確定する。
6. システムはパーツと制約をカタログに登録する。
7. システムは「登録しました」と表示する。

**代替フロー**

- 1a. 新しい部位を追加する場合、管理者は部位名を入力する。システムは部位を作成してから2へ進む。
- 5a. 管理者が取り消した場合、何も登録せずに終了する。

**例外フロー**

- 2a. 検証エラーがある場合、システムはエラーの項目と理由を表示し、登録しない。
- 3a. 制約の参照先パーツが存在しない場合、システムはエラーを表示し、登録しない。

図: [ロバストネス図](svg/uc2_03_robustness.svg) ／ [シーケンス図](svg/uc2_03_sequence.svg)

## 2-04 組み合わせ制約

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 組み合わせ制約 |
| アクター | 利用者(2-05、2-08から包含) |
| 概要 | パーツを変更するとき、その組み合わせが制約ルールに違反しないかを判定する。違反する選択肢は選べない状態にし、理由を示す。 |
| 事前条件 | 2-05でパーツの変更が要求された、または2-08で保存仕様が呼び出された。 |
| 事後条件 | 違反がなければ変更が許可される。新しい仕様で選べなくなった選択肢は、パーツ棚で無効になり、理由が表示される。 |

**基本フロー**

1. システムは現在の仕様に変更を加えた、仮の仕様を作る。
2. システムは車両の制約ルールをすべて評価する。
3. 違反がなければ、システムは変更を許可する。
4. システムは仮の仕様で選べなくなる選択肢を求め、パーツ棚で無効にする。理由はその選択肢に表示する。

**代替フロー**

- 3a. 排他ルールに違反し、そのルールが自動解決できる場合(例: ネイキッド化するとスクリーンを外す)、システムは相手のパーツを外した仕様で許可し、その旨を通知する。

**例外フロー**

- 3b. 自動解決できない違反がある場合、システムは変更を許可せず、ルールの説明文を表示する。

図: [ロバストネス図](svg/uc2_04_robustness.svg) ／ [シーケンス図](svg/uc2_04_sequence.svg)

## 2-05 パーツ・塗装選択

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | パーツ・塗装選択 |
| アクター | 利用者 |
| 概要 | 部位ごとのパーツや塗装の色を選び、車両ビューとビルドシートにすぐ反映する。 |
| 事前条件 | 2-01でベース車両が選ばれている。 |
| 事後条件 | 現在の仕様が更新され、変更が履歴に1件積まれる。車両ビューとビルドシート(重量、シート高など)が更新される。 |

**基本フロー**

1. 利用者はパーツ棚、または車両ビューの部位をクリックして、パーツを選ぶ。
2. システムは組み合わせ制約を判定する(2-04を包含)。
3. システムは変更前と変更後の仕様を、変更履歴として記録する。
4. システムは現在の仕様を変更後の仕様にする。
5. システムは車両図を描画し直し、ビルドシートの値を計算し直して表示する。

**代替フロー**

- 1a. 塗装の色を選んだ場合、システムは制約判定をせずに3へ進む。
- 1b. 候補にない色を使う場合、利用者はカラーピッカーで色を指定する。
- 1c. プリセットを選んだ場合、システムは複数の部位をまとめて変更し、変更履歴には1件として記録する。

**例外フロー**

- 2a. 制約に違反した場合、システムは2-04の結果(理由)を表示し、仕様を変更しない。

図: [ロバストネス図](svg/uc2_05_robustness.svg) ／ [シーケンス図](svg/uc2_05_sequence.svg)

## 2-06 取り消し

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 取り消し |
| アクター | 利用者 |
| 概要 | 直前の変更を取り消す。取り消した変更はやり直すこともできる。 |
| 事前条件 | 変更履歴が1件以上ある(元に戻すボタンが有効)。 |
| 事後条件 | 仕様が1つ前の状態に戻り、車両ビューとビルドシートが更新される。取り消した変更はやり直し用に残る。 |

**基本フロー**

1. 利用者は「元に戻す」を押す(またはCtrl+Z)。
2. システムは取り消し用の履歴から直前の変更を取り出す。
3. システムは変更前の仕様を現在の仕様にする。
4. システムは取り出した変更を、やり直し用の履歴に移す。
5. システムは車両図とビルドシートを更新し、ボタンの有効・無効を切り替える。

**代替フロー**

- 1a. 利用者が「やり直す」を押した場合(Ctrl+Shift+Z)、システムはやり直し用の履歴から変更を取り出し、変更後の仕様を現在の仕様にして、取り消し用の履歴に戻す。
- 補足. 新しい変更(2-05)を行うと、やり直し用の履歴は空になる。

**例外フロー**

- 2a. 履歴が空の場合、ボタンは無効になっているため、この操作は行えない。

図: [ロバストネス図](svg/uc2_06_robustness.svg) ／ [シーケンス図](svg/uc2_06_sequence.svg)

## 2-07 ビフォーアフター比較

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ビフォーアフター比較 |
| アクター | 利用者 |
| 概要 | ベース車両の標準仕様(ビフォー)と、現在の仕様(アフター)を並べて比較する。変更した部位と重量の差も一覧で示す。 |
| 事前条件 | 2-01でベース車両が選ばれている。 |
| 事後条件 | 比較を閉じると編集画面に戻る。比較によって仕様は変わらない。 |

**基本フロー**

1. 利用者は「比較」を押す。
2. システムは現在の仕様と、車両の標準仕様を取得する。
3. システムは両方の車両図を描画する。
4. システムは2つの仕様の差分(部位、変更前、変更後、重量差)を求める。
5. システムは2つの図を左右に並べ、差分の一覧と一緒に比較画面に表示する。
6. 利用者は比較画面を閉じる。システムは編集画面に戻る。

**代替フロー**

- 2a. 利用者が保存一覧から比較相手を選んだ場合、システムは標準仕様の代わりにその保存仕様をビフォーとして使う。
- 5a. 利用者が「重ねて表示」を選んだ場合、システムは2つの図を重ね、スライダーで境目を動かして比べられるようにする。

**例外フロー**

- 4a. 差分がない場合、システムは「ノーマルから変更はありません」と表示する。

図: [ロバストネス図](svg/uc2_07_robustness.svg) ／ [シーケンス図](svg/uc2_07_sequence.svg)

## 2-08 仕様保存・呼出

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 仕様保存・呼出 |
| アクター | 利用者 |
| 概要 | 現在の仕様に名前を付けてブラウザに保存し、あとで一覧から呼び出す。不要になった仕様は削除できる。 |
| 事前条件 | 保存: 2-01でベース車両が選ばれている。呼出: 保存済みの仕様が1件以上ある。 |
| 事後条件 | 保存: 保存一覧に1件追加される。呼出: 選んだ仕様が現在の仕様になり、車両ビューに表示される。 |

**基本フロー**

1. 【保存】利用者は名前を入力して「保存」を押す(省略時は「ビルド #番号」)。
2. システムは現在の仕様を取得し、名前と保存日時を付けて保存仕様を作る。
3. システムは保存仕様をブラウザの保存領域に書き込む。
4. システムは保存一覧を更新する。

**代替フロー**

- 【呼出】A1. 利用者は保存一覧から仕様を選ぶ。
- A2. システムは保存領域から保存仕様を読み込む。
- A3. 車両が現在と異なる場合、システムは車両を切り替える(2-01の4〜6)。
- A4. システムは組み合わせ制約で整合性を確認する(2-04を包含)。
- A5. システムは仕様を現在の仕様にし、変更履歴を消去する。
- A6. システムは車両図とビルドシートを更新する。
- 【削除】D1. 利用者は一覧の削除ボタンを押し、確認に答える。システムは保存領域から削除して一覧を更新する。

**例外フロー**

- 3a. 保存領域が使えない、または容量を超えた場合、システムは「保存できませんでした」と理由を表示する。
- A4a. 登録が消えたパーツを含む場合、システムはその部位を標準パーツに置き換え、置き換えた部位を通知する。

図: [ロバストネス図](svg/uc2_08_robustness.svg) ／ [シーケンス図](svg/uc2_08_sequence.svg)

## 2-09 PDF保存

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | PDF保存 |
| アクター | 利用者 |
| 概要 | 完成した車両図とビルドシート(部品、色、諸元)を、1枚のPDFにして端末に保存する。 |
| 事前条件 | 2-01でベース車両が選ばれている。 |
| 事後条件 | PDFファイルが利用者の端末に保存される。仕様は変わらない。 |

**基本フロー**

1. 利用者は「PDF保存」を押す。
2. システムは出力ダイアログを表示する(用紙の向き、ビフォー図を含めるか)。
3. 利用者は条件を選び、「出力」を押す。
4. システムは現在の仕様で車両図を描画し、画像に変換する。
5. システムはパーツ情報から部品表、色、諸元(重量、シート高)の表を作る。
6. システムはタイトル、日時、図、表を配置したPDFを作る。
7. システムは「スタイル名_日付.pdf」という名前でPDFを渡す。

**代替フロー**

- 3a. 「ビフォー図を含める」を選んだ場合、システムは標準仕様の図も描画し、並べて配置する。

**例外フロー**

- 6a. PDFの作成に失敗した場合(日本語フォントが読み込めないなど)、システムはエラーを表示する。
- 7a. ブラウザがダウンロードを許可しない場合、システムはPDFを新しいタブで開く。

図: [ロバストネス図](svg/uc2_09_robustness.svg) ／ [シーケンス図](svg/uc2_09_sequence.svg)
