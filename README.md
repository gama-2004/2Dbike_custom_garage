# 2Dカスタムガレージ

バイクを真横から見た2Dの図で、パーツや塗装を組み替えてカスタム後の見た目を確かめられるWebアプリ。卒業研究のプロジェクト。

実車を改造する前に、仕上がりのイメージと変更内容をつかめるようにすることをねらいにしている。

## 使い方

### React 版(`web/`)

React＋TypeScript＋Vite で作り直した版。Node.js 22 以降が必要。

```
cd web
npm install      # 初回だけ
npm run dev      # 開発用サーバー(表示された URL をブラウザで開く)
npm test         # 単体テスト
npm run build    # 公開用のファイルを web/dist/ に作る
```

`web/dist/` は相対パスで作るので、GitHub Pages などどのフォルダに置いても動く。画面の切り替えは URL の `#custom` などで持つ。

画面は次の5つ。

| 画面 | URL | 内容 |
| --- | --- | --- |
| トップ | `#top` | サイトの概要、おすすめのカスタム例 |
| 車種選択 | `#select` | ベース車両を選ぶ |
| カスタム | `#custom` | 左にパーツのカテゴリ一覧(サムネイル付き)、中央に2D表示、右に選択中のパーツと合計金額 |
| 比較 | `#compare` | ノーマル(または保存したカスタム)と並べる・重ねる。変更点と価格・重量の差 |
| マイページ | `#mypage` | 保存したカスタムの読み込み・比較・名前の変更・削除 |
| 管理画面 | `/admin`(または `#admin`) | 管理者ログイン、ベース車両追加、パーツ追加(サーバーが動いているときだけ) |

サーバーが動いていないとき(GitHub Pages や、ファイルだけで開いたとき)は、組み込みの2車種だけで動き、保存先はブラウザになる。

### サーバーとデータベース(`server/`)

Node.js＋Express＋MySQL のサーバー。車両・パーツのカタログと保存したカスタム、管理者を MySQL に持つ。画面(`web/`)はサーバーにつながると自動でこちらを使う。

**初回の準備(Windows)**

1. MySQL 8.4 LTS を入れる。https://dev.mysql.com/downloads/mysql/ で Version に「8.4.x LTS」、OS に「Microsoft Windows」を選び、「Windows (x86, 64-bit), MSI Installer」をダウンロードする(ログインを求められたら「No thanks, just start my download.」)。インストール後に開く MySQL Configurator で root のパスワードを決める(控えておく)。「MySQL Installer」のページから入るのは 8.0(サポート終了)なので使わない。
2. `server` フォルダで、設定ファイルを作る。
   ```
   cd server
   copy .env.example .env
   ```
   `.env` をメモ帳で開き、`DB_PASSWORD` に1で決めた root のパスワード、`SESSION_SECRET` に長いでたらめな文字列、`ADMIN_PASSWORD` に管理者のパスワード(8文字以上)を書く。`.env` は GitHub に上げない(`.gitignore` 済み)。
3. パッケージを入れて、データベースを作る。組み込みの2車種と管理者が登録される。
   ```
   npm install
   npm run db:init
   ```
   「unknown plugin auth_gssapi_client」と出たら、3306番では MySQL ではなく MariaDB(XAMPP など)が動いている。MySQL 8.4 を別の番号(3307 など)で動かし、`.env` の `DB_PORT` をその番号にする。このアプリは MySQL 8.4 の書き方を使うので、MariaDB では動かない。

   **インストールできないとき(学校の PC など)** MySQL 8.4 の「Windows (x86, 64-bit), ZIP Archive」を `C:\Users\<ユーザー名>\mysql84` に展開し、`server` フォルダで `mysql-local.cmd` を実行する(開いたままにする)。3307番で動き、root のパスワードは空。`.env` は `DB_PORT=3307`、`DB_PASSWORD=`(空)にする。

**毎回の起動(開発)** コマンドプロンプトを2つ開く。

```
cd server
npm run dev        # サーバー(http://localhost:3000)
```
```
cd web
npm run dev        # 画面(http://localhost:5173)。/api はサーバーに中継される
```

画面は http://localhost:5173/ 、管理画面は http://localhost:5173/admin 。

**本番(1台で公開する)** `web` で `npm run build` してから、`server` で `npm start` すると、http://localhost:3000/ で画面と API の両方が動く。

**そのほかのコマンド**(`server` フォルダで)

| コマンド | 内容 |
| --- | --- |
| `npm run db:reset` | データベースを消して作り直す(保存したカスタムも消える) |
| `npm run admin:add -- <ログインID> <パスワード> [氏名]` | 管理者を追加する。同じIDならパスワードを変え、ロックも解除する |
| `npm test` | API のテスト(`<DB_NAME>_test` というデータベースを作り直して使う) |

**定義ファイル** 管理画面で読み込む車両定義・パーツ定義の見本は `web/public/samples/` にある(管理画面の「サンプルを読み込む」でも使える)。形式と検証の内容は `web/src/catalog/definition.ts` に書いてある。定義ファイルで追加する車両は、後輪の中心を (215, 322)、前輪の中心を (590, 322) にして描く。`{{main}}` のように書くと、その塗装部位の色に置き換わる。

### プロトタイプ(`app/`)

`app/index.html` をブラウザで開くだけで動く(ビルドやインストールは不要)。React 版の元になった1ファイル版で、車両図の描き方は同じ。

GitHub Pages で公開する場合は、リポジトリの Settings → Pages で公開元のブランチを選ぶと、`https://<ユーザー名>.github.io/<リポジトリ名>/app/` で開ける。

## 現在できること

- ベース車両の選択: スーパースポーツ、アメリカンの2種(どちらもジャンルを参考にしたオリジナルデザイン)
- 部位ごとのパーツ選択、3色(メイン・サブ・ライン)の塗装とグラフィック柄
- ローダウン(車高)の調整
- プリセット(サーキット仕様、ボバー、チョッパーなど)と、ランダムな組み合わせ
- スタイル名の自動判定
- ビルドシート(部品一覧、シート高・最低地上高・車両重量の目安)
- 車体の部位クリックで設定欄へ移動
- 仕様の保存・呼び出し(プロトタイプはブラウザ。React 版はサーバーの MySQL、サーバーがないときはブラウザ)
- React 版のみ: パーツごとの参考価格と合計金額、ノーマルとの比較(並べる・重ねる)、保存名の指定と変更、拡大表示
- React 版＋サーバー: 管理者ログイン、車両定義ファイルによるベース車両の追加、パーツ定義ファイルによるパーツと組み合わせ制約の追加

パーツの価格は画面づくりのための仮の値で、実在する製品の価格ではない。

## フォルダ構成

```
.
├── web/                    React 版(React 19＋TypeScript＋Vite＋Zustand)
│   ├── public/samples/     管理画面で読み込む定義ファイルの見本
│   └── src/
│       ├── api/            サーバーの API を呼ぶ
│       ├── catalog/        車両データ、カタログと定義ファイルの形式・検証(サーバーと共通)
│       ├── render/         車両図の描画(仕様 → SVG)
│       ├── store/          作業状態(現在の仕様)
│       ├── logic/          組み合わせ制約の判定、価格の計算、比較の差分、ブラウザ保存
│       ├── repo/           仕様の保存・呼出(サーバー、またはブラウザ)
│       ├── pages/          画面(トップ、車種選択、カスタム、比較、マイページ、管理)
│       └── components/     画面部品(パーツ選択、2D表示、選択中のパーツ、ヘッダー)
├── server/                 サーバー(Node.js＋Express 5＋MySQL)
│   ├── src/app.ts          API
│   ├── src/catalogRepo.ts  カタログ・仕様の読み書き
│   ├── src/scripts/        データベースの初期化、管理者の追加
│   ├── test/               API のテスト
│   └── .env.example        設定ファイルの見本
├── app/
│   └── index.html          プロトタイプ(1ファイル構成)
├── docs/
│   ├── 01_ガントチャート.xlsx                 工程表(担当・日程・進捗)
│   ├── 04_2026_基本設計書_R4S1_ARMY.docx    基本設計書(サーバー＋DB構成、10機能)
│   ├── sql/schema.sql      テーブル作成SQL(MySQL 8.4、基本設計書の別紙3)
│   ├── requirements.md     必要機能一覧(全25機能、非機能要件、評価方法)
│   ├── tech-selection.md   使用技術の検討(React)
│   ├── tech-selection.xlsx 同上の表(Excel)
│   ├── database.md         データベースのテーブル定義(案)
│   └── glossary.md         用語集(「仕様」の定義など)
└── uml/
    ├── README.md           設計図の一覧
    ├── usecases.md         ユースケース記述(9件)
    ├── design.html         全図とユースケース記述をまとめた閲覧ページ
    ├── puml/               PlantUMLソース(20本)
    ├── svg/                描画済みの図(20枚)
    ├── model.py            図とユースケース記述の定義
    ├── render.py           puml/ と svg/ を生成
    └── gen_html.py         design.html を生成
```
